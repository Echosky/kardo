=== n04 | 02 NULLs and CASE | Bucket with CASE

=== j11 | 03 Joins | Join fan-out
Joining `order_items` and `payments` to the same order multiplies rows, which inflates any SUM. For orders that have more than one payment, return `order_id`, the number of order lines `lines`, the number of payments `payments`, and the row count you get from joining both to the order `joined_rows`.
--- hint
Joining two child tables to one parent multiplies rows (lines × payments). Count each child separately, then compare with COUNT(*) of the double join.
--- solution
SELECT o.order_id,
  (SELECT COUNT(*) FROM order_items i WHERE i.order_id = o.order_id) AS lines,
  (SELECT COUNT(*) FROM payments p WHERE p.order_id = o.order_id) AS payments,
  (SELECT COUNT(*) FROM order_items i JOIN payments p ON p.order_id = i.order_id WHERE i.order_id = o.order_id) AS joined_rows
FROM orders o
WHERE (SELECT COUNT(*) FROM payments p WHERE p.order_id = o.order_id) > 1;

WHERE e.department = 'Sales' AND e.title LIKE '%Associate%'
GROUP BY e.employee_id, e.full_name;

=== j13 | 03 Joins | Full outer join
Compare customers (`customer_id`) with CRM contacts. CRM ids look like `C-00042`. Return each distinct customer id that appears in either source, as `customer_id, in_shop, in_crm` where the flags are 1 or 0.
--- hint
Turn `C-00042` into 42 with `CAST(SUBSTR(contact_id, 3) AS INTEGER)`. SQLite 3.39+ supports FULL OUTER JOIN; the result here has as many rows as customers since every CRM contact is a customer. Remember to dedupe the CRM side first and skip blank ids.
--- solution
WITH crm AS (
  SELECT DISTINCT CAST(SUBSTR(contact_id, 3) AS INTEGER) AS customer_id
  FROM raw_crm_contacts WHERE contact_id LIKE 'C-%'
)
SELECT COALESCE(c.customer_id, crm.customer_id) AS customer_id,
       CASE WHEN c.customer_id IS NULL THEN 0 ELSE 1 END AS in_shop,
       CASE WHEN crm.customer_id IS NULL THEN 0 ELSE 1 END AS in_crm
FROM customers c FULL OUTER JOIN crm ON crm.customer_id = c.customer_id;

=== a09 | 04 Aggregation | Payments that don't add up
Find orders whose total payments don't match the order total. Compare `ROUND(SUM(amount), 2)` per order with the item total. Consider only orders that have at least one payment. Return `order_id, order_total, paid` where the two differ by more than 0.01.
--- hint
Aggregate each table to the order grain first (two subqueries or CTEs), then join. Joining raw rows first causes fan-out.
--- solution
WITH t AS (SELECT order_id, ROUND(SUM(quantity * unit_price * (1 - discount)), 2) AS order_total FROM order_items GROUP BY order_id),
     p AS (SELECT order_id, ROUND(SUM(amount), 2) AS paid FROM payments GROUP BY order_id)

WHERE ABS(t.order_total - p.paid) > 0.01;

=== a11 | 04 Aggregation | GROUP_CONCAT / STRING_AGG

=== a14 | 04 Aggregation | ROLLUP-style subtotals

=== c02 | 06 CTEs | Chained CTEs
Build it in steps: CTE 1 = order totals for completed/shipped orders with customer_id; CTE 2 = lifetime value per customer; final = the top 10 customers by lifetime value as `customer_id, first_name, ltv` (2 decimals), highest first.
--- solution
WITH order_totals AS (
  SELECT o.order_id, o.customer_id, SUM(oi.quantity * oi.unit_price * (1 - oi.discount)) AS total

), ltv AS (
  SELECT customer_id, SUM(total) AS ltv FROM order_totals GROUP BY customer_id
)
SELECT c.customer_id, c.first_name, ROUND(l.ltv, 2) AS ltv
FROM ltv l JOIN customers c ON c.customer_id = l.customer_id
ORDER BY l.ltv DESC LIMIT 10;

=== c05 | 06 CTEs | Import / logic / final pattern
dbt projects write models as import CTEs, then logic CTEs, then a final select. Write one: import `orders` and `payments`, compute paid amount per order, and return `status`, the number of orders and the total paid (2 decimals) per status, including statuses with no payments (paid shows 0).
--- solution
WITH orders_src AS (SELECT * FROM orders),
payments_src AS (SELECT * FROM payments),
paid AS (SELECT order_id, SUM(amount) AS paid FROM payments_src GROUP BY order_id),
final AS (
  SELECT o.status, COUNT(*) AS orders, ROUND(COALESCE(SUM(p.paid), 0), 2) AS paid
  FROM orders_src o LEFT JOIN paid p ON p.order_id = o.order_id GROUP BY o.status
)
SELECT * FROM final;

=== c06 | 06 CTEs | Replace a nested subquery
This query nests three levels deep. Rewrite it with CTEs and return the same result:
`SELECT country, AVG(n) FROM (SELECT c.country, c.customer_id, COUNT(o.order_id) n FROM customers c LEFT JOIN orders o ON o.customer_id=c.customer_id GROUP BY c.country, c.customer_id) GROUP BY country`
Round the average to 2 decimals.
--- solution
WITH per_customer AS (
  SELECT c.country, c.customer_id, COUNT(o.order_id) AS n
  FROM customers c LEFT JOIN orders o ON o.customer_id = c.customer_id
  GROUP BY c.country, c.customer_id
)
SELECT country, ROUND(AVG(n), 2) FROM per_customer GROUP BY country;

=== c08 | 06 CTEs | Data quality check in CTEs
In one row, using a CTE per check, return: number of orders with no items (`orders_without_items`), number of order items pointing at a missing product (`orphan_items`), and number of non-cancelled orders with no payment (`unpaid_orders`).
--- solution
WITH no_items AS (SELECT COUNT(*) AS n FROM orders o WHERE NOT EXISTS (SELECT 1 FROM order_items i WHERE i.order_id = o.order_id)),
orphans AS (SELECT COUNT(*) AS n FROM order_items i WHERE NOT EXISTS (SELECT 1 FROM products p WHERE p.product_id = i.product_id)),
unpaid AS (SELECT COUNT(*) AS n FROM orders o WHERE o.status <> 'cancelled' AND NOT EXISTS (SELECT 1 FROM payments p WHERE p.order_id = o.order_id))

=== c09 | 06 CTEs | Customer 360 model
Build a customer summary with CTEs: one row per customer with `customer_id`, `orders` (all statuses), `first_order`, `last_order`, `is_subscriber` (1/0, ever subscribed) and `net_revenue` (completed/shipped only, 2 decimals, 0 if none). Include customers with no orders.
--- solution
WITH order_totals AS (
  SELECT o.order_id, SUM(oi.quantity * oi.unit_price * (1 - oi.discount)) AS total
  FROM orders o JOIN order_items oi ON oi.order_id = o.order_id GROUP BY o.order_id
), cust_orders AS (
  SELECT o.customer_id, COUNT(*) AS orders, MIN(o.order_date) AS first_order, MAX(o.order_date) AS last_order,
         SUM(CASE WHEN o.status IN ('completed','shipped') THEN t.total ELSE 0 END) AS net_revenue
  FROM orders o JOIN order_totals t ON t.order_id = o.order_id GROUP BY o.customer_id
), subs AS (SELECT DISTINCT customer_id FROM subscriptions)
SELECT c.customer_id, COALESCE(co.orders, 0) AS orders, co.first_order, co.last_order,
       CASE WHEN s.customer_id IS NULL THEN 0 ELSE 1 END AS is_subscriber,
       ROUND(COALESCE(co.net_revenue, 0), 2) AS net_revenue
FROM customers c LEFT JOIN cust_orders co ON co.customer_id = c.customer_id
LEFT JOIN subs s ON s.customer_id = c.customer_id;

=== r11 | 07 Recursive CTEs | Cycle guard
Recursive CTEs loop forever on cyclic data. The setup adds a cycle: employee 1 now reports to 25. Walk down from employee 1 and return the distinct `employee_id`s reached, stopping when an id is already on the path. (Without a guard this times out.)
--- setup
UPDATE employees SET manager_id = 25 WHERE employee_id = 1
--- hint
Carry the visited path as text like `,1,5,19,` and add `WHERE instr(t.path, ',' || e.employee_id || ',') = 0`. Postgres 14+ has a `CYCLE` clause for this. Using UNION instead of UNION ALL also stops exact duplicate rows.
--- solution
WITH RECURSIVE walk(employee_id, path) AS (
  SELECT 1, ',1,'
  UNION ALL
  SELECT e.employee_id, w.path || e.employee_id || ','
  FROM employees e JOIN walk w ON e.manager_id = w.employee_id
  WHERE instr(w.path, ',' || e.employee_id || ',') = 0
)
SELECT DISTINCT employee_id FROM walk;

Join on `customer_id` AND `order_date >= valid_from AND (valid_to IS NULL OR order_date < valid_to)`.
--- solution
WITH h AS (
  SELECT customer_id, segment, changed_at AS valid_from, LEAD(changed_at) OVER (PARTITION BY customer_id ORDER BY changed_at) AS valid_to
  FROM segment_changes
)
SELECT h.segment, COUNT(*) FROM orders o JOIN h ON h.customer_id = o.customer_id
  AND o.order_date >= h.valid_from AND (h.valid_to IS NULL OR o.order_date < h.valid_to)
WHERE o.order_date LIKE '2025-%' GROUP BY h.segment ORDER BY h.segment;

=== e11 | 12 Analytics engineering (dbt style) | Incremental merge with late updates
A merge-strategy incremental model upserts on a `unique_key`. The setup creates `dim_contacts(customer_id PRIMARY KEY, email, updated_at)` loaded only from the `2025-12-01` CRM load. Merge in the `2025-12-02` load: for each customer keep the row with the newest updated_at, inserting new customers and updating existing ones only if the incoming row is newer. The checker returns count and number of distinct emails.
--- setup
CREATE TABLE dim_contacts(customer_id INTEGER PRIMARY KEY, email TEXT, updated_at TEXT);
INSERT INTO dim_contacts SELECT customer_id, email, updated_at FROM (
  SELECT CAST(SUBSTR(contact_id, 3) AS INTEGER) AS customer_id, NULLIF(LOWER(TRIM(email)), '') AS email, updated_at,
         ROW_NUMBER() OVER (PARTITION BY contact_id ORDER BY updated_at DESC) AS rn
  FROM raw_crm_contacts WHERE contact_id LIKE 'C-%' AND _loaded_at = '2025-12-01 02:00:00') WHERE rn = 1
--- hint
Dedupe the new batch first with ROW_NUMBER, then `INSERT ... ON CONFLICT (customer_id) DO UPDATE SET ... WHERE excluded.updated_at > dim_contacts.updated_at`. In SQLite an upsert from a SELECT needs `WHERE true` before ON CONFLICT.
--- solution
INSERT INTO dim_contacts (customer_id, email, updated_at)
SELECT customer_id, email, updated_at FROM (
  SELECT CAST(SUBSTR(contact_id, 3) AS INTEGER) AS customer_id, NULLIF(LOWER(TRIM(email)), '') AS email, updated_at,
         ROW_NUMBER() OVER (PARTITION BY contact_id ORDER BY updated_at DESC) AS rn
  FROM raw_crm_contacts WHERE contact_id LIKE 'C-%' AND _loaded_at = '2025-12-02 02:00:00'
) WHERE rn = 1
ON CONFLICT (customer_id) DO UPDATE SET email = excluded.email, updated_at = excluded.updated_at
WHERE excluded.updated_at > dim_contacts.updated_at;
--- check
SELECT COUNT(*), COUNT(DISTINCT email), MAX(updated_at) FROM dim_contacts;

=== e14 | 12 Analytics engineering (dbt style) | Mart: daily KPIs
Build `mart_daily_kpis` for December 2025 with a date spine: `day`, `orders` (completed/shipped), `customers` (distinct, same orders), `revenue` (2 decimals, 0 when none), `new_customers` (customers whose first-ever order was that day), every day present, in order.
--- solution
WITH RECURSIVE spine(day) AS (SELECT '2025-12-01' UNION ALL SELECT date(day, '+1 day') FROM spine WHERE day < '2025-12-31'),
good AS (
  SELECT o.order_id, o.customer_id, o.order_date, SUM(oi.quantity * oi.unit_price * (1 - oi.discount)) AS total
  FROM orders o JOIN order_items oi ON oi.order_id = o.order_id WHERE o.status IN ('completed','shipped')
  GROUP BY o.order_id, o.customer_id, o.order_date
),
firsts AS (SELECT customer_id, MIN(order_date) AS first_day FROM orders GROUP BY customer_id),
daily AS (SELECT order_date AS day, COUNT(*) AS orders, COUNT(DISTINCT customer_id) AS customers, SUM(total) AS revenue FROM good GROUP BY order_date),
newc AS (SELECT first_day AS day, COUNT(*) AS n FROM firsts GROUP BY first_day)
SELECT s.day, COALESCE(d.orders, 0), COALESCE(d.customers, 0), ROUND(COALESCE(d.revenue, 0), 2), COALESCE(n.n, 0)
FROM spine s LEFT JOIN daily d ON d.day = s.day LEFT JOIN newc n ON n.day = s.day ORDER BY s.day;
--- options
